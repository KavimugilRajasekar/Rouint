## Overview

An environment in Rouint is a named base URL — the scheme, host, and port (if any) that prefixes every endpoint path. Environments are stored separately from endpoint definitions, so you can test the same endpoint against local, staging, or production without changing the endpoint config.

```
local       →  http://127.0.0.1:8080
staging     →  https://staging.myapp.com
production  →  https://api.myapp.com
```

---

## Managing Environments

```bash
rouint add-base-url
```

```
? What would you like to do?
❯ Add a new base URL
  Delete an environment
  Cancel
```

### Adding an Environment

```
? Enter the base URL:           https://staging.myapp.com
? Enter a label for this URL:   staging
```

**Validation:**
- Must start with `http://` or `https://`
- Must have a non-empty host
- Trailing slashes are stripped automatically

The environment is saved to `.rouint-data/environments/staging.json`:

```json
{
  "base_url": "https://staging.myapp.com"
}
```

### Deleting an Environment

Select **Delete an environment**, choose from the list, and confirm. The deletion is immediate.

## Using Environments at Test Time

When you run `rouint start-test`, you first select the endpoint, then the environment:

```
? Select an endpoint:
❯ Login            [POST]   /api/v1/auth/login
  Get User By ID   [GET]    /api/v1/users/{id}
  — Exit —

? Select base URL:
❯ local       →  http://127.0.0.1:8080
  staging     →  https://staging.myapp.com
  production  →  https://api.myapp.com
```

The final request URL is constructed as:

```
<base_url> + <path with resolved placeholders>
```

**Example:**

```
https://staging.myapp.com + /api/v1/users/usr-101
→ https://staging.myapp.com/api/v1/users/usr-101
```

## Environment Storage

Environment files live in `.rouint-data/environments/` and are **gitignored** by default. This prevents real server URLs (especially production) from being committed to version control.

```
.rouint-data/
└── environments/       ← gitignored
    ├── local.json
    ├── staging.json
    └── production.json
```

Each file contains only the base URL:

```json
{
  "base_url": "https://api.myapp.com"
}
```

---

## Git Safety

The `.rouint-data/.gitignore` generated by `rouint init` protects:

```gitignore
environments/    # never committed
.temp_token      # never committed
bodies/          # never committed
*.secret.json    # never committed
```

Safe to commit: `endpoints/`, `registry.json`, `config.json`

This means your endpoint definitions (paths, methods, headers, auth types) are shareable with your team, but base URLs and live tokens stay local.

## Typical Setup

A common multi-environment setup for an API project:

| Label | URL | When to use |
|-------|-----|-------------|
| `local` | `http://127.0.0.1:8080` | Development — server running on your machine |
| `staging` | `https://staging.myapp.com` | Pre-production verification |
| `production` | `https://api.myapp.com` | Live environment |

You do not need all three. Add only what you actually use.

## No Environments Configured

If you run `rouint start-test` without any environments:

```
✘  No base URLs configured.
   Run: rouint add-base-url
```

You must have at least one environment before running tests.
